### See the storm before it reaches the grid.

Transparent, weighted storm-risk scoring for Ontario distribution operators — wind, canopy, flood exposure, outage history, and historical severe weather fused into zone-level risk tiers, with an LLM-generated response brief.

</div>

---

## Overview

Voltex takes Ontario, divides it into **673 H3 hexagonal zones** (~22 km each), fetches live weather from Environment Canada for each zone centroid, joins local static layers (tree canopy density, flood footprints, outage history, and historical severe weather patterns), and produces:

- a normalized **risk score (0–1.00)** with an explicit **Low / Medium / High** tier per zone,
- a **zone choropleth map** — hexagons colored green → amber → red by risk,
- a **per-factor breakdown** showing raw value, normalized score, weight, and contribution across **5 factors**,
- a **plain-language operator brief** generated by Gemini (or a deterministic local fallback when no key is set),
- an **interactive map** with zone polygons, monitored city pins, a layer mode toggle, and an **Ontario explore view**.

Operators can also search any Ontario address to add a custom pin scored against the same model. Everything that goes into the score is shown back to the operator. No black-box numbers.

## Stack

- **Next.js 16** (App Router) — frontend + API routes in one process
- **TypeScript** end-to-end
- **Tailwind v4** + custom design tokens (Emil-Kowalski-flavored easing, stagger, scale-on-press)
- **Leaflet** + Carto dark basemap for the zone choropleth and city pin map
- **H3** hexagonal spatial indexing for zone geometry
- **Nominatim (OSM)** for geocoding
- **Environment Canada MSC GeoMet** for live weather
- **Google Gemini** for the operator narrative (optional, transparent fallback)

## Scoring model

```
risk_score = clamp01(
    0.25 × wind
  + 0.20 × canopy
  + 0.15 × flood
  + 0.20 × outage_history
  + 0.20 × severe_weather_history
)
```

Tiers: `< 0.40 Low`, `0.40–0.69 Medium`, `≥ 0.70 High`. Weights, normalization, and inputs are all surfaced in the UI.

## Data

Raw datasets live under `datasets/` (gitignored) and are preprocessed into small derived JSON indices under `datasets/derived/` via:

```bash
npm run build:data   # runs build-indices + build-hex-grid + build-weather-history
```

Sources are documented in [`datasets/README.md`](datasets/README.md).

## Getting started

```bash
npm install
npm run build:data    # one-time, ~10–20s, builds derived indices
cp .env.example .env  # optional, add GEMINI_API_KEY for live narratives
npm run dev
```

Then open <http://localhost:3000>.

## Project layout

```
app/
  api/assess/route.ts         Orchestrates geocode → weather → score → narrative
  api/assess-batch/route.ts   Batch-scores monitored cities (no LLM)
  api/assess-zones/route.ts   Scores all H3 hex zones across Ontario
  api/narrative/route.ts      Generates LLM briefing from scored payload
  page.tsx                    Landing page → dashboard
components/
  RiskDashboard.tsx           Main dashboard: map, pins, zones, panels, HUD
  ZoneLayer.tsx               Leaflet hex polygon choropleth layer
  ZoneLegend.tsx              Color ramp legend overlay
  ZoneDetailPanel.tsx         Zone detail panel with weather history profile
  FactorBreakdown.tsx         5-factor score explainability
  RiskGauge.tsx, BriefingReport.tsx, …
lib/
  geocode.ts                  Nominatim + fetchWithTimeout
  weather.ts                  MSC GeoMet parsing
  datasets.ts                 Derived-index lookups (FSA, canopy, flood, hex grid, weather history)
  scoring.ts                  5-factor weighted formula + scoreZone()
  llm.ts                      Gemini call + local fallback
  fetchWithTimeout.ts         Reliability wrapper
scripts/
  build-indices.mjs           Streaming preprocessor (311, canopy, flood)
  build-hex-grid.mjs          H3 resolution-4 hex grid generator
  build-weather-history.mjs   Synthetic severe weather history
```
